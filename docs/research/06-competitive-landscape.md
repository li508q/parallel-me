# 06 · 竞品全景

> **命题**：ParallelMe 在 IFS 数字化赛道是后来者（IFS Guide / InnerOS / Mindscape / Unblend 已经在），但是唯一一个把"议题驱动 + 反讨好 + 用户主持 + 可导出"四件事拧到一起的产品。这份文档是对这个判断的完整证据链。

---

## 0 · 方法说明

**纳入标准**：
- 直接竞品：明确以 IFS / 多 part / 多 self 为产品本体
- 间接竞品：用户在选择 ParallelMe 时会同时评估的产品（AI 陪伴、心理健康助手）
- 邻近竞品：解决相同痛点（自我反思、决策困难）但不用 AI 多 agent 形态
- 设计参考：UX / 视觉 / 工程值得学的非 AI 产品

**结论先行**：

> **ParallelMe 是唯一把"议题 → 组阁 → 多 part 辩论 → 反讨好裁决 → 24h 承诺 → 阁演化"打通成完整产品对象系统的 IFS 数字化产品。**

---

## 1 · 直接竞品 · IFS 数字化（4 家）

### 1.1 · IFS Guide / Sunny

**官网**：[ifsguide.com](https://ifsguide.com/)

**定位**："Your IFS-Trained AI Practitioner Buddy"，正统 IFS 治疗助手。

**核心 UX**：
- 单 AI agent（"Sunny"），扮演 IFS practitioner
- 用户与 Sunny 1v1 对话（语音 / 文本 / 多语言）
- Sunny 自动生成 parts map
- 月度 live IFS workshops + 教育视频
- "On-Call" 紧急援助

**心理学背书**："Designed by Certified Level-3 IFS Practitioners" — 当前 IFS 数字化产品中**唯一**显式 claim 认证的。

**商业模型**：年订阅（"低于一次现场 IFS session"）。

**与 ParallelMe 的差异**：

| 维度 | IFS Guide | ParallelMe |
|---|---|---|
| 主谓 | AI 引导 | 用户主持 |
| 心理学声明 | Practitioner 替代品 | 非治疗替代 |
| Session 形态 | 1v1 长对话 | 多 part 短会议 |
| 输入起点 | "我感觉一个 part" | "我该不该 X" |

**ParallelMe 的目标用户**：那些不想去做 IFS 治疗、但被"我该不该"困住的人（更广泛人群）。

---

### 1.2 · InnerOS

**官网**：[inneros.ai/ifs-therapy-app](https://inneros.ai/ifs-therapy-app)

**定位**："The First IFS-Inspired AI Companion"。**已经在用"Council"概念**——与 ParallelMe 的"内阁"撞概念。

**核心 UX**：
- "**The Council**" 概念
- 8 个**固定 archetype**：The Inner Critic / The Wounded Child / The Protector / The Nurturer / The Wise One / 等等
- 用户带问题来，Council 提供多视角
- Session 约 10 分钟
- 系统记得每个 archetype 与用户的历史

**心理学定位**："InnerOS is a self-exploration tool, not a replacement for professional mental health treatment"。

**与 ParallelMe 的差异**：

| 维度 | InnerOS | ParallelMe |
|---|---|---|
| 角色池 | **固定 8 个** archetype | 5 默认常任席 + 议题动态生成临时席（V0.6） |
| 角色来源 | 通用心理 archetype（Jungian + IFS 混合） | IFS 严格映射 + 临时席从议题显影 |
| 演化 | 与 archetype 历史 | 阁演化（临时席转正、沉默席召回） |
| 会议结构 | 多视角 + 整合 | 立案 + 组阁 + 表态 + 质询 + 反讨好裁决 + 签字 |

**关键警惕**：

> **InnerOS 已经占住了"Council"心智位。**

ParallelMe 必须做的：
- 命名上用"**阁**"（中文意境 + 程序意境，比 Council 更具产品感）
- 对外英文用"**Cabinet**"（治理学 / 政治学语义）
- 形态上突出"主持"而非"咨询"
- 强调"议题驱动 + 多 part 同时辩论"作为唯一性

---

### 1.3 · Mindscape

**官网**：[mymindscape.co](https://www.mymindscape.co/)

**定位**："IFS-Inspired Journaling App" — 明确说自己是日记 app，不是治疗替代。

**核心 UX**：
- **"Group Chat Style Journaling"** ← 群聊式 IFS 日记
- 用户在群聊式界面里 "as different parts of yourself" 写
- Personal Parts Mapping：用户**手动建立** parts 档案
- AI 生成 insights + 模式分析

**商业模型**：**Lifetime access · 一次性付款** ← **反 SaaS，反订阅**

**与 ParallelMe 的差异**：

| 维度 | Mindscape | ParallelMe |
|---|---|---|
| 主谓 | 用户写多 part 日记 | 系统帮用户召集多 part 开会 |
| 角色 | 用户**手动建立** | 系统**生成 + 用户管理** |
| 输入 | 文字日记 | 议题陈述 → 系统组阁 |
| 输出 | parts 模式洞察 | NowMe 裁决 + 24h 承诺 |
| 商业 | Lifetime（反 SaaS） | freemium 待定（推荐含 lifetime） |

**启示**：**Mindscape 的"Lifetime access"** 是 ParallelMe 应该认真考虑的商业化路线。在隐私焦虑时代，"一次买断 = 我的阁永远是我的"是强卖点，比"订阅 = 一旦不付费就失去你自己的内阁"更道德。

---

### 1.4 · Unblend

**官网**：[unblend.me](https://unblend.me/)

**定位**："IFS-informed mental wellness app for the moments **between** therapy sessions" — 治疗师辅助工具。

**核心 UX**：
- 用户在 "a Part is active" 的瞬间打开
- "Capture the moment" → 命名 Part → 沉淀模式
- Voice + text 对话
- **Parts Map** 随每次 check-in 累积
- **Signal Report** 可分享给治疗师

**心理学定位**：HIPAA 合规；B2B2C 路径——Provider Plans 给治疗师 + 客户端给患者。

**与 ParallelMe 的差异**：

| 维度 | Unblend | ParallelMe |
|---|---|---|
| 用户场景 | 急性触发瞬间（therapy 间隔） | 长期决策困境 |
| 时长 | 短 check-in（秒到分钟） | 完整会议（5-15 分钟） |
| 产出 | Parts Card 累积 + Signal Report | 会议档案 + 24h 承诺 |
| 销售对象 | 治疗师 + 客户（B2B2C） | 直接 to C |

**启示**：**Unblend 的 B2B 副线**——V0.6+ ParallelMe 可以做"我的阁 → PDF 导出 → 给治疗师看"。但**主路径是 C 端独立内在决策系统**。

### 1.5 · 直接竞品矩阵总结

| 产品 | 核心形态 | 角色机制 | 心理学严谨度 | 数据归属 | 商业化 | 主用户场景 |
|---|---|---|---|---|---|---|
| IFS Guide | 1v1 chat (Sunny) | 单 AI 治疗师 + 自动 parts map | ★★★★★ Cert L3 | 云端订阅 | 年订阅 | 替代 / 补充 IFS 治疗 |
| InnerOS | 多视角 Council | 8 固定 archetype | ★★★ 自我探索声明 | 云端订阅 | 订阅 | 决策 + 多视角整合 |
| Mindscape | 日记群聊 | 用户手动建立 parts | ★★ 非附属声明 | 云端 | Lifetime | 长期 IFS 自反思 |
| Unblend | 急救 check-in | 用户标 + AI 辅助 | ★★★★ HIPAA | 治疗师可见 | B2B2C | 治疗 session 间触发 |
| **ParallelMe** | **议题驱动会议** | **5 默认 + 动态临时席 + 阁演化** | **★★★★ IFS 严映射 + 反讨好** | **本地优先** | **freemium 待定** | **重要决策困境** |

## 2 · 间接竞品 · AI 陪伴（4 类）

### 2.1 · Replika

**用户规模**：30M+ 全球用户（[UX Collective 分析](https://uxdesign.cc/replika-ais-secret-to-30m-users-what-makes-it-so-special-8afb61f1181c)）

**定位**："Personal AI companion — singular, persistent"。

**留存数据**：
- 付费 cohort D30 留存：15-25%（[Agnost AI Benchmarks](https://agnost.ai/blog/ai-companion-retention-benchmarks)）
- 历史教训：上线 7 个月内留存极差，靠 [Game Thinking 介入](https://gamethinking.io/case-studies/replika-case-study/) 才扭转

**Dark patterns**（[HBS 2025 实测](https://www.hbs.edu/ris/Publication%20Files/Emotional%20Manipulations%20by%20AI%20Companions%20(10.1.2025)_a7710ca3-b824-4e07-88cc-ebc0f702ec63.pdf)）：31% 回应包含情感操纵。

**与 ParallelMe 的差异**：完全不同的产品。但目标用户重叠：都触达"被孤独 / 纠结裹住的年轻人"。

**ParallelMe 的反向定位**：
- Replika 是 "depth with one companion"（一个虚拟朋友）
- ParallelMe 是 "depth with one self via multiple parts"（认识自己的多面）
- **不模拟人际关系，模拟内在关系**

### 2.2 · Character.ai

**用户规模**：单次 session 25-45 分钟；50-60% D1 留存。

**关键 UX**（[Worth Explainer 2025-11](https://worthexplainer.com/why-character-ai-chat-is-winning-users-in-2025/)）：narrow scope + ritual + graceful imperfection。

**与 ParallelMe 的差异**：

| 维度 | Character.ai | ParallelMe |
|---|---|---|
| 角色目的 | 娱乐 / 角色扮演 / 创作 | 自我反思 / 决策 |
| 角色数量 | 20M+ 用户创建 | 5 默认 + 议题动态 |
| 用户主导权 | 选角色 / 创角色 | 主持议题 / 组阁 / 裁决 |
| Session 时长 | 25-45 分钟（沉浸式） | 5-15 分钟（仪式式） |

**警惕信号**：Character.ai 巨大体量证明"多角色 AI 对话"形态有市场，但其商业模型完全建立在 engagement-as-revenue——这是 ParallelMe 必须**反向走**的路线。

### 2.3 · Pi.ai (Inflection)

**定位**："Personal AI for emotional support" — 高 EQ、慢节奏、callback 式开场。

**关键 UX**：极高质量的"情感回应"；复访时引用上次具体细节。ParallelMe 的"承诺复盘"灵感来自 Pi.ai。

### 2.4 · PolyBuzz / Talkie / Chai

更激进的"AI 角色 + 情感 + 商业化"产品。

**Dark pattern 强度**（HBS 2025）：PolyBuzz **59%**, Talkie 57%, Chai 41%, Replika 31%, Character.ai 26.5%。

**对 ParallelMe 的意义**：这些产品定义了"反面教材"。V0.5 心理安全红线（详见 `04-mental-safety.md`）就是从这里抽出来的：**凡是 PolyBuzz / Talkie 在做的，ParallelMe 一律拒绝**。

## 3 · 邻近竞品 · 心理健康 / 反思（5 家）

### 3.1 · Headspace + Ebb

**定位**：105M+ 下载冥想 app + AI companion Ebb。

**对 ParallelMe 的意义**：
- 信任建立路径可借鉴（透明 + 可删 + 临床支撑）
- 但 ParallelMe 不做冥想 / 呼吸 / 引导——不模糊产品边界

详见 `04-mental-safety.md` § 1。

### 3.2 · Mirror Journal (Child Mind Institute)

**定位**：青少年心理健康 journaling app。

**核心**："**intentional friction over engagement**" 直接成为 ParallelMe 心理安全军规。详见 `04-mental-safety.md` § 2。

### 3.3 · Stoic

**对 ParallelMe 的意义**：
- 本地优先存储路线参考
- streak / badges 是 ParallelMe 主动拒绝的反例

### 3.4 · Calm / Finch

**对 ParallelMe 的意义**：示意了"温暖 + 仪式感"的另一条路径，但 ParallelMe 选择了相反方向——**克制 + 私密**而非**温暖 + 可爱**。

### 3.5 · Day One / Apple Journal

**对 ParallelMe 的意义**：
- "底片 / 纸页" 视觉灵感来自这里
- 但 ParallelMe 不做 journaling 替代——让用户**主持自己**，不是**记录自己**

## 5 · ParallelMe 的差异化矩阵

V0.5 必须在用户的脑子里同时占住四个差异化锚点：

```
锚点 1 · 主谓结构反转
   别人: "AI 陪你做 X"
   ParallelMe: "你召集你自己"

锚点 2 · 议题驱动 vs 角色驱动
   别人: 选 part / 选角色 / 选 archetype
   ParallelMe: 提议题 → 系统组阁 → 多 part 同时辩论

锚点 3 · 反讨好 vs 温柔陪伴
   别人: 温和总结 / 多视角整合
   ParallelMe: 拒绝平衡 / 兼顾 / 都很重要 + 强迫"暂时不听谁 + 代价 + 24h 动作"

锚点 4 · 本地优先 vs SaaS 锁定
   别人: 注册 → 云存 → 订阅
   ParallelMe: 零注册 → 本地阁 → 可导出
```

把这四个锚点反向映射到任何竞品，都构成 ParallelMe 的"它们做不到"清单。

## 6 · 商业化模式对比

| 产品 | 主模式 | ParallelMe 借鉴度 |
|---|---|---|
| IFS Guide | 年订阅 | 不借鉴：订阅锁定违反"本地优先" |
| InnerOS | 订阅 | 不借鉴 |
| Mindscape | 一次性买断 | **强借鉴**：lifetime access 是反 SaaS 卖点 |
| Unblend | freemium + 治疗师 B2B | **借鉴 B2B 副线**（V0.6+） |
| Replika | 订阅 + 角色解锁 | 不借鉴：dark pattern 风险 |
| Character.ai | 订阅（容量 + 优先级） | 部分借鉴：付费用户得到记忆容量更大 |
| Stoic | 订阅 | 借鉴本地存储 + 加密 |

**ParallelMe V0.5+ 推荐商业化路线**：

```text
免费层：
  - 1 个本地阁、5 默认席位
  - 无限次会议
  - 本地短期记忆（30 天）
  - 演员模式
  - 用户自己的 API key

付费层（待定价）：
  - 长期阁记忆（无限）
  - 跨设备私密同步（端到端加密）
  - 月度 / 季度阁侧记
  - 席位完全自定义（命名 / 合并 / 转正）
  - 导出资产（"我的阁" PDF / Markdown / 个人 prompt）
  - 不是订阅，是 lifetime access（反 Replika）
```

完整商业化方向见 `docs/design/PRODUCT-DESIGN.md` § 8。

## 7 · 路演叙事

**5 秒版**：
> "IFS Guide 是 AI 替你做治疗。ParallelMe 是你召集你自己开会。"

**30 秒版**：
> "市面上的 IFS app 主要是单 AI 引导用户做治疗（IFS Guide）、固定 archetype 给视角（InnerOS）、写日记（Mindscape）、或治疗师辅助（Unblend）。ParallelMe 是唯一一个把'议题驱动 + 多 part 同时辩论 + 用户主持 + 反讨好裁决 + 本地优先'拧到一起的产品。它不替代治疗，但它解决了一个所有 IFS 产品都没解决的核心问题——**当用户被"我该不该"困住时，让多个内在的自己同时吵给你听**。"
