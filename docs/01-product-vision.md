# 产品愿景

![Confusion to alignment](images/core-concept-confusion-to-alignment.png)

ParallelMe 面向的不是普通选择题，而是那些让人反复想起、难以启齿、无法只靠利弊表解决的重大选择。

它的基本判断是：

> 很多难选的事，不是因为用户缺建议，而是因为几个真实的内在保护者正在守护不同的东西。

因此，ParallelMe 不从“答案”开始。它先定义问题，再让冲突显形，最后让用户亲手确认自己愿意承担的方向。

## 设计初衷

ParallelMe 希望帮助用户完成这样的移动：

```text
我一直在想这件事
  -> 我终于知道这件事真正问我的是什么
  -> 我能听见不同部分的我分别在保护什么
  -> 我知道选择一个方向会得罪哪些声音、付出哪些代价
  -> 我能在 24 小时内做一个小而真实的动作
```

最终产物不是外部建议，而是用户能认领的自我落定。

## 目标用户

ParallelMe 最适合这些处境：

- 要不要辞职、转岗、考公、回老家或继续留在大城市
- 要不要结婚、分手、搬家、远行或与家人重新谈边界
- 要不要用稳定交换自由，或用高风险交换生命力
- 明知道自己疲惫，却又害怕停下来会落后
- 反复在金钱、安全感、关系、意义和未来感之间拉扯

如果问题只是低风险事实查询、简单推荐或纯计算，ParallelMe 并不是最合适的工具。

## 第一性原则

1. **先定义，再讨论**

   用户不应该带着一团情绪直接进入圆桌。书记员必须先帮助用户确认本次议题。

2. **矛盾不是失败**

   每一种拉扯都先被当作保护，而不是错误。声音之间的分歧正是产品要显影的内容。

3. **任何一声都不能冒充整个我**

   疲惫、金钱恐惧、出走冲动、家庭牵挂和未来视角都重要，但都不能单独接管方向盘。

4. **用户始终坐在中间**

   系统可以命名、追问和收束，但用户可以确认、反对、改写和归档。

5. **行动必须小到可以完成**

   本心落定不是宏大宣言，而是一个 24 小时内能执行、有完成标准的小动作。

## 权威依据

ParallelMe 的设计借鉴以下传统，但不把自身包装为治疗或诊断系统：

| 传统 | 产品转译 |
| --- | --- |
| 金字塔原理 | 阶段一议题定义、4-Key 结构和 MECE 式收束。 |
| Internal Family Systems | 每个声音都有保护意图、恐惧、盔甲、代价和渴望。 |
| Voice Dialogue | 让不同内在立场分开说话，而不是被合成一个 AI 助手。 |
| Schema Therapy Modes | 理解同一困惑中可能被激活的不同应对模式。 |
| Chairwork | 给不同立场不同座位，让用户可以继续听某一声或让两声对话。 |
| ACT | 最终回到价值、痛苦接纳和承诺行动。 |
| Motivational Interviewing | 不争辩、不强行说服，而是让矛盾自然显形。 |
| Narrative Therapy / CFT | 外化问题，降低疲惫、恐惧和逃避带来的羞耻感。 |

## 产品边界

ParallelMe 不做：

- 临床诊断
- 治疗替代
- 危机干预替代
- 替用户做最终决定
- 把结构化 schema 展示成产品体验
- 为了兼容旧逻辑保留与 v1 语义冲突的设计

ParallelMe 要做：

- 放慢困惑
- 命名冲突
- 让不同保护者有座位
- 让代价被看见
- 把最终确认权交还给用户

## 产品承诺

ParallelMe 应当像一间私密房间：用户把混乱放进去，出来时不一定轻松，但更知道自己正在握住什么。

它追求的情绪结果不是马上舒服，而是重新拥有选择的作者身份。
