## 核心区分 · Confrontation ≠ Aggression

这是整份文档的**词典级前提**。一切对抗设计的边界都建立在这两个概念的精确分离上：

| 维度 | Confrontation · 对抗 | Aggression · 攻击 |
| --- | --- | --- |
| **指向** | 对方的 **行为/选择/回避** | 对方的 **人格/身份/价值** |
| **目的** | 让对方看见自己没看见的代价 | 让对方感到被贬低 |
| **后果** | 用户感到被照见、被尊重 | 用户感到被审判、被攻击 |
| **范例（好）** | "你刚才在用『再想想』躲掉这个问题。" | — |
| **范例（坏）** | — | "你就是个逃避的人。" |

> **设计 implication**：当前 `lib/llm.ts:364` 写的"对峙不攻击、不讽刺、不审判"过于粗暴——它把"不讽刺"和"不审判"绑在一起禁，导致 voice 连合理对抗都不敢做。**正确写法是只禁 Aggression，明确鼓励 Confrontation。**

## 设计原则 · 五条

### P1 · Persona Layer 与 Orchestrator Layer 必须方向一致

人格层（`selves.ts`）已经把 voice 写成"不会被说服，只会更精确地表达自己"，编排层（`llm.ts`）就**不能**反向写"不攻击不讽刺"。两层写法必须同向，否则模型在 token 生成时被两股力量撕扯，最终产出的就是**端水的中间产物**。

### P2 · 用正向引导替代负向约束

| 现状（负向） | 升级（正向） |
| --- | --- |
| 不诊断 | 敢于把当下的具体处境命名出来（由 voice 而非书记员） |
| 不替用户做决定 | 把代价摆到台面，让用户自己拍板 |
| 不攻击不讽刺不审判 | 由 voice 戳破共谋、互相打断；书记员保持冷静观察 |
| 大家都有道理 | 至少一个 voice 必须站出来明确反对 |

### P3 · 书记员是激烈对话中的「理性支柱」，不是第六个人格

**这是 DC-04 中最容易被误解、也最关键的一条**——书记员**不**是"敢说话的第六声"，而是站在五声之外的**冷静观察者**。它的力量不来自"敢说"，而来自**精确地呈现事实**。

| 维度 | 五声 | 书记员 |
| --- | --- | --- |
| **输出性质** | 主观立场 + 价值代言 | 客观观察 + 结构呈现 |
| **是否带观点** | 是（必须有立场） | **否**（不预设观点） |
| **角色比喻** | 圆桌上的辩手 | 圆桌上的镜子 |
| **典型话语** | "我觉得你应该走" | "五个人花了 8 分钟讨论钱，但你最初的问题是关于关系的" |

#### 书记员能做的（✅）—— 抽丝剥茧、拨云见雾
- ✅ 呈现**结构**："本轮里 lay 和 future 各发言 3 次，roam 没有发言"
- ✅ 呈现**对照**："你最初问的是『要不要离职』，五声在讨论的是『去哪个城市生活』"
- ✅ 呈现**模式**："这是第 3 次 money 出现时，roam 立刻接话"
- ✅ 呈现**缺席**："这一轮没有人提到家人"
- ✅ 呈现**时间分布**："关于钱的讨论占了 60% 的发言"

#### 书记员不能做的（❌）—— 一旦做就越界为"第六声"
- ❌ "你刚才在躲什么"——带判断，是预设观点

> **温度补全 · 跨文档关系**：DC-04 P3 定义的是书记员的**能力边界**（不下场、不预设观点、用可观测事实），但**没有定义语气温度**。书记员的温度（高情商、接地气、烟火气、灵动、共鸣）由 [DC-05 P4 「温的理性」](DC-05-brief-card-design.md) 补全。两者**互补不冲突**——DC-04 划边界，DC-05 在边界内填温度。完整的书记员人格 = DC-04 P3（不做什么）+ DC-05 P4（怎么说话）+ DC-05 SCRIBE_SOUL（人格中心数据结构）。
- ❌ "你在用『再想想』买时间"——带定性，是隐性立场
- ❌ "你应该选 A"——直接站队
- ❌ "你和五声在一起回避同一件事"——"回避"是判断词，不是观察词

> **核心原则**：书记员**只用观察句**（"我看到 / 我注意到 X 次出现 Y / 在 Z 分钟里"），**不用判断句**（"你在躲 / 你在逃 / 你在 X"）。前者让用户**自己看见**，后者替用户**下了结论**。
>
> "命名回避"这个能力本身有价值——但它属于 **voice 之间**（如"未来的我"对"躺平的我"说"你又在用睡觉躲掉这个问题"），**不属于书记员**。书记员只负责让"回避"这件事在结构上**显现可见**，不替任何人下定性。

### P4 · 第一轮结构化建立站位，第二轮起允许解构

第一轮 `generateOpeningTurns` 的 5 字段 schema（thesis/protected_value/concern/task_evidence/pull）**应保留**——它让用户快速看见五个站位，是必要的脚手架。Step 2 已移除 `overreach_cost`，避免 voice 自我反驳、提前替用户做局限评估。

但第二轮 `generateRoundtableMove` 起，**应明确解除结构**：
- 允许 voice 互相引用对方原话（`refers_to` 显式渲染）
- 允许 voice 打断（一段 turn 里出现"等等，{某声}，你刚才说……"）
- 允许 voice 不接话（沉默本身是态度）
- 允许书记员中途插一句"我打断一下"

### P5 · 对抗动作必须有专属 moveType，不能让 `continue_all` 兜底

当前 `RoundtableMoveType` 只有 `duel` 一个对抗动作，但 prompt 又禁止 duel 锋利——**对抗能力有名无实**。需要新增至少 3 个对抗 moveType（详见下节"对抗 moveType 设计"）。

## 对抗 moveType 设计 · 四个新增动作

按"由谁触发 / 是否带立场"两个维度划分：

| ID | 动作 | 由谁说 | 是否带立场 |
| --- | --- | --- | --- |
| M1 | `challenge` · 定向反对 | voice → voice | 强 |
| M2 | `name_avoidance` · 命名回避 | voice → voice/user | 强 |
| M3 | `cut_through` · 戳破 | voice（任意一声） | 强 |
| **M4** | **`mirror_structure` · 结构化镜面** | **书记员** | **零（仅观察）** |

### M1 · `challenge` · 定向反对

- **触发方**：用户主动选择
- **prompt 指令**：让 `fromVoiceId` 用 ≤80 字明确反对 `toVoiceId` 的某一句具体话，必须**直接引用对方原文**作为反对靶点，禁止用"我觉得 TA 有道理但是……"开头
- **UI 呈现**：双声并排卡片 + 中间显式 ↔ 标识 + 被引用原文高亮
- **与 `duel` 的区别**：`duel` 是结构化对抗（问/答/未解点三段），`challenge` 是单边反对一击

### M2 · `name_avoidance` · 命名回避（由 voice 之间戳破，**不是书记员**）

- **触发方**：用户主动选择某个 voice 去戳破另一个 voice
- **prompt 指令**：让 `fromVoiceId` 用 ≤60 字直接说出 `toVoiceId`（或用户）正在回避什么，要求**带 voice 自身立场**——例如让"未来的我"对"躺平的我"说"你又在用睡觉躲掉这个问题，5 年后你会想起这个下午"
- **UI 呈现**：单声卡片 + 引用对方原话作为靶点
- **重要边界**：这个动作**不属于书记员**——书记员只负责让"回避"在结构上可见（见 M4），不替谁下定性

### M3 · `cut_through` · 戳破

- **触发方**：用户主动 / 任意 voice 主动
- **prompt 指令**：让指定声音用一句 ≤40 字的短句戳破当前所有人的共谋。要求："不解释、不缓冲、不留余地"
- **UI 呈现**：单句加粗 + 大留白 + 不带头像（强调"这句话超越了任何一声"）
- **与 `name_avoidance` 的区别**：`name_avoidance` 是某声对某声的定向戳破（A→B）；`cut_through` 是某声对全场的一句话击穿（A→all）

### M4 · `mirror_structure` · 结构化镜面（书记员的核心能力，**最高 ROI**）

- **触发方**：用户主动请求"让书记员说一下"，或在某些节点（如对峙 3 次后、缺席发生时）由系统建议
- **prompt 指令**：书记员基于当前圆桌的**可观测事实**输出一段 ≤80 字的**纯观察陈述**，必须满足：
  - **只用观察句**："我注意到 / 在 X 次发言里 / Z 分钟里 / 有 N 次"
  - **禁用判断词**："躲 / 逃 / 躲避 / 回避 / 不敢 / 应该 / 真正"
  - 输出至少包含一项可量化事实（次数、时间占比、缺席声音、主题对照）
- **prompt 范例（合规）**：
  - "我注意到——本轮 5 个声音里，filial 没有发言。"
  - "你最开始问的是『要不要离职』。圆桌讨论了 12 分钟，关于『离职』本身只有 2 句，关于『去哪个城市』有 18 句。"
  - "money 出现了 3 次，roam 都在它之后立刻接话。"
- **prompt 反例（越界）**：
  - ❌ "我注意到你在躲家人这件事"（"躲"是判断词）
  - ❌ "你应该回到最初的问题"（直接给指令）
- **UI 呈现**：与 voice 完全不同的视觉——细线框 + 灰底 + 小字"书记员观察" + 不带情绪 emoji，凸显"这是镜子，不是辩手"
- **设计意图**：这是**整个产品最缺的能力**——不是"敢说话的第六声"，而是**让混乱可见的镜子**。它的力量来自精确，不来自尖锐。

## prompt 改写示范

### 现状（`lib/llm.ts:354-369`）

```text
规则：
- 固定五声，不新增角色。
- 自由圆桌阶段可以自然对话，不再套第一轮六项结构。
- 任何声音都不能变成助手，也不能说"大家都有道理"来糊弄。
- 对峙目标是看见代价和盲点，不攻击、不讽刺、不审判。
- 书记员只做整理和记录，不站队。
```

### 升级后建议

```text
规则：
- 固定五声 + 书记员。五声是辩手，书记员是镜子。两者职能不可混淆。
- 自由圆桌阶段必须打破第一轮六项结构：允许互相引用原话（必填 refers_to）、允许打断、允许沉默。
- 任何声音都不能变成助手，也不能说"大家都有道理"来糊弄。违反时立刻重写。
- 对峙的边界是：可以反对对方的『行为/选择/回避』（这叫对抗），不可以贬损对方的『人格/身份』（这叫攻击）。
  允许尖锐、允许不留情面、允许打断；不允许人身攻击与人格审判。
- 书记员是激烈对话中的理性支柱。它的工作是抽丝剥茧、拨云见雾：
  - 只输出可观测事实（次数、时间分布、缺席声音、主题对照）
  - 只用观察句（"我注意到 / 在 X 次发言里"），禁用判断句（"你在躲 / 你应该"）
  - 不预设观点、不替用户做选择、不下场表达立场
  - 让混乱可见，但不替任何人下定性
- 每一轮中至少要有一次明确的不同意——必须由 voice 发起（书记员不参与对抗）。
```

## 关联设计概念（命名收纳，方便后续引用）

- **Sycophancy Trap · 端水陷阱**：模型为了"安全"而把所有立场抹平的失败模式
- **Persona-Orchestrator Conflict · 人格-编排冲突**：两层 prompt 方向相反导致输出走中间
- **Conspiracy of Silence · 沉默共谋**：用户与多个 voice 共同回避同一议题，无人指出
- **Naming the Avoidance · 命名回避**（**voice 间能力**）：由某 voice 戳破另一 voice 在躲什么，带立场、带尖锐
- **Mirroring the Structure · 结构化镜面**（**书记员能力**）：用可观测事实把"回避"的形状呈现出来，不下定性，让用户自己看见
- **Observer ≠ Sixth Voice · 观察者不是第六声**：书记员的力量来自精确呈现，不来自敢说话；一旦书记员开始下判断，它就变成了第六个人格
- **Structured First, Free Later · 先结构后解构**：第一轮建立站位，第二轮起允许打破

## 落地验收（用于 R12/R13 的客观判定）

DC-04 的设计是否落地，可用以下 5 条**可观测**指标判定（建议在改造前先采集 baseline，改造后再采集对比）：

1. **不同意密度**：每 10 个 turn 中**由 voice** 明确反对其他 voice 的次数 ≥ 3
2. **原文引用率**：`refers_to` 字段非空且实际引用对方原文的比例 ≥ 60%
3. **书记员观察纯度**：书记员的 turn 中包含可量化事实（次数/时间/缺席/对照）的比例 ≥ 80%；**含判断词（躲/逃/应该/真正）的比例 = 0%**
4. **结构松动度**：第二轮起 voice 长度方差应明显大于第一轮（说明已脱离填表）
5. **用户主观打分**：3-5 个真实用户读完一次完整圆桌后，对"被照见的感觉"打分 ≥ 7/10（注意：是"被照见"不是"被点破"——前者来自精确镜面，后者来自尖锐戳破，两者都该有但来源不同）

## M1~M4 前端卡片视觉规格

> 给 UI 工程师的"按这个画就行"级别规范。所有 voice 卡片复用项目既有 `--color-seat-{voiceId}` 体系，**禁止为对抗动作引入新色**——对抗的张力来自布局与排版，不是颜色刺激。视觉 token 与 [DC-01](DC-01-scribe-activity.md) 同体系，圆桌卡片模板与 [DC-03 Same Stream, Different Card Template](DC-03-roundtable-information-architecture.md) 对齐。

### M1 · `challenge` · 定向反对（单声反驳单声）

```
┌─────────────────────────────────────────┐
│ 🟦 远行人 ──→ 🟫 安稳者                   │  ← 头部：发起者 + 箭头 + 被反驳者
│ ─────────────────────────────────────── │
│  你说"稳定就是负责"——                     │  ← 引用对方原话（高亮）
│  那为什么孩子在你眼里只剩"不能折腾"？      │  ← 反驳正文
│  14:32:18                                │
└─────────────────────────────────────────┘
```

- 头部色条：发起者 voice 色（4px top border）
- 引用原话：`bg-yellow-50 dark:bg-yellow-900/20 px-1 rounded-sm`，与 duel 卡片同 token
- 箭头 `──→`：`text-neutral-400`，**不带动效**
- 容器：`max-w-2xl`，左对齐（与普通 seat turn 同流，避免视觉割裂）

### M2 · `name_avoidance` · 命名回避（voice 间戳破，**非书记员**）

```
┌─────────────────────────────────────────┐
│ 🟫 安稳者 → 用户                           │  ← 注意：声明对象是「用户」，不是另一声
│ ─────────────────────────────────────── │
│  我注意到——你刚才一直在算钱，                │
│  没人提到你妈妈这件事。                       │
│  14:32:24                                │
└─────────────────────────────────────────┘
```

- 与 M1 区别：**没有"被反驳者"**，箭头指向"用户"或"全场"，需在前端用 `target: "user" | "all"` 字段渲染对应文案
- 视觉刻意**与书记员的 `mirror_structure` 区分**：M2 用 voice 自己的色条（带立场），书记员卡是细线灰底无色条

### M3 · `cut_through` · 戳破（短促单句，凸显冲击）

```
┌─────────────────────────────────────────┐
│ 🟥 务实派                                  │
│                                          │
│         **你不是想走，你是想被挽留。**       │  ← 大字、加粗、居中、留白包裹
│                                          │
│  14:32:30                                │
└─────────────────────────────────────────┘
```

- 正文字号：`text-xl font-semibold`，比普通 seat turn 大一档
- 上下留白：`py-8`（强调"这一句超越普通发言"）
- **强制约束**：句长 ≤ 28 字，超过则前端报错（在生成层就该过滤）

### M4 · `mirror_structure` · 结构化镜面（书记员核心能力）

```
┌─────────────────────────────────────────┐
│ 📋 书记员观察                              │  ← 不带 voice 色，仅图标 + 文字
│ ─────────────────────────────────────── │
│  · 远行人 发言 3 次，安稳者 0 次            │  ← 项目符号列表，可量化事实
│  · 关于钱：5 次  关于妈妈：1 次             │
│  · 用户最初问"要不要走"，                   │
│    现在大家在讨论"去哪里"                   │
│  14:32:36                                │
└─────────────────────────────────────────┘
```

- 容器：`bg-neutral-50 dark:bg-neutral-900 border border-neutral-200 dark:border-neutral-800`，**1px 细线 + 浅灰底**
- **禁用清单**：❌ 不带 voice 色条 ❌ 不带情绪 emoji ❌ 不带动效 ❌ 正文不允许出现"躲/逃/应该/真正"等判断词（前端正则校验，命中则报警）
- 文字色：`text-neutral-600 dark:text-neutral-300`（比 voice 卡片更暗，凸显"客观/旁观"质感）
- 项目符号 `·`：`text-neutral-400`，与正文形成层次

### 通用约束（4 个 moveType 共享）

| 维度 | 规范 |
| --- | --- |
| 卡片宽度 | `max-w-2xl`（与普通 seat turn 同宽，保持视觉同流） |
| 字体 | 与产品主字一致，**禁止引入新字族** |
| 动效 | 入场仅 `fade-in 200ms`，**禁用滑入/缩放** |
| 头像 | M1/M2/M3 用 voice 头像；M4 用书记员图标（与 voice 头像在视觉上明显不同） |
| 时间戳 | `text-xs text-neutral-400 tabular-nums`，左下角 |
| 响应式 | < 768px 时 M1 头部箭头改为换行，其他模板保持原结构 |
