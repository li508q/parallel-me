# ParallelMe v0.6 · Interaction Patterns

> 交互方向：用户不是填表的人，也不是观看 AI 输出的人。用户是五声会谈的主持者。

## 1. Core Surface

会谈页由三个持久区域组成：

- **Stage Rail**：只显示四个大阶段：困惑成形 / 五声入席 / 五声对话 / 清明落定。
- **Timeline**：记录陈情、工作焦点、五声表态、用户追问、换位回答、互问澄清和 NowMe。
- **Host Console**：底部固定主持人台，用户随时能补充、暂停、追问、修正。

主体验不是普通聊天流。Timeline 是会谈记录，Host Console 是用户介入位置。

## 2. Four Big Stages

### 困惑成形

对象：

- 陈情纸
- 追问纸条
- 工作焦点纸

门槛：

- 用户必须确认或改写工作焦点，不能直接进入五声。

### 五声入席

对象：

- 五张固定声音牌

每张声音牌展示：

- 激活理由
- 保护什么
- 最怕什么

门槛：

- 五声都生成后，才能进入对话。

### 五声对话

对象：

- 五声表态
- 点名追问
- 换位回答
- 五声互问

门槛：

- 用户至少追问一声。
- 用户可以选择换位回答一声。

### 清明落定

对象：

- 清明句
- NowMe 结构化输出
- 24h 承诺
- 记忆同意

门槛：

- 清明句可改写。
- 24h 承诺必须具体可执行。
- 记忆必须用户确认后才保存。

## 3. Voice Card Actions

点击某一声的声音牌，打开操作面板：

- `追问`：向这声问一句。
- `换位回答`：用户坐到这声的位置，替它说得更准。
- `这句不准`：用户指出当前表达哪里不像自己。

这比复杂文本命令更可靠，也更符合椅子技术的“换位”体验。

## 4. Host Console Intent

文本输入保留，但不是唯一入口。

轻量意图：

- `pause`：暂停推进。
- `continue`：继续下一步。
- `ask_voice`：追问当前已选声音。
- `note`：只记录，不触发流程。
- `correct`：修正工作焦点、清明句或某声表达。

原则：

- 点击声音牌后，输入默认绑定该声。
- 没选声音时，输入优先作为 note 或 correct。
- 低置信度不触发动作。
- 触发前给用户可撤销确认。

## 5. Timeline Turn Types

| Kind | 用途 |
| --- | --- |
| `petition` | 用户陈情 |
| `scribe` | 中性侧记、阶段推进 |
| `focus` | 工作焦点 |
| `voice` | 五声表态 |
| `user` | 用户追问、补充、修正 |
| `followup` | 被点名声音回答 |
| `role-reversal` | 用户换位回答 |
| `cross-clarification` | 五声互问 |
| `clarity` | 清明句与 NowMe |
| `commitment` | 24h 承诺 |

所有 turn 都应可回看，不用“返回上一步”找内容。

## 6. My Voices

`我的声音` 是长期空间。

五声卡片应显示：

- 出现次数
- 最响次数
- 被追问次数
- 被换位回答次数
- 最近出现时间
- 一句长期画像

声音详情页应显示该声跨会谈的活动史，而不是单次记录的附属物。

## 7. Safety Interactions

危机表达触发：

- 停止普通会谈推进。
- 显示“ParallelMe 不能替代真人危机支持”。
- 提供即时真人资源。
- 不生成清明句、建议、承诺。

非危机但高风险表达：

- 将承诺压低到 24h 小动作。
- 不鼓励重大不可逆行为。
