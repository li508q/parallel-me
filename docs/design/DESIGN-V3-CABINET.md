# ParallelMe V3 · 内在组阁系统产品设计

> 本文是 ParallelMe 从「五声 demo」升级为「可管理、可调用、有记忆的内在组阁系统」的产品设计宪法。
> 它先不讨论技术选型，只定义产品定位、心理学约束、核心对象、用户流程、视觉美学、UI 交互和长期形态。

---

## 0 · 结论先行

ParallelMe 的根本需求不是「帮用户做决定」。

它真正解决的是：

> 当用户被焦虑、纠结、内耗、关系压力和选择困难裹住时，帮助用户把混乱的内在声音组织成一个可被看见、可被对话、可被管理、可被长期调用的内在决策系统。

一句话定位：

> **ParallelMe 是你的私人内阁，专门处理那些没人能替你决定的事。**

更锋利一点：

> **不是 AI 替你想清楚，而是 AI 帮你召集你自己。**

产品核心从 V2 到 V3 的跃迁：

| V2 | V3 |
|---|---|
| 5 个固定分身吵一架 | 每个议题临时组阁 |
| 用户输入一次，然后观看 | 用户在立案、组阁、质询、裁决中持续参与 |
| 分身是 prompt 角色 | 席位是有记忆、有关系、有权力变化的内在组织 |
| 历史是对话记录 | 历史是会议档案，会改变用户的阁 |
| 五声是产品本体 | 阁是产品本体，五声是初始模板 |

---

## 1 · 根本需求定位

### 1.1 表层需求

用户会带着这些问题来：

- 我该不该辞职？
- 我该不该考公？
- 我该不该分手？
- 我该不该回老家？
- 我该不该创业？
- 我为什么总想逃？
- 我为什么知道该做什么，但就是不做？

这些看起来是决策问题。

但如果产品只给建议，就会变成普通 AI assistant。

### 1.2 深层需求

用户真正想要的是：

- 我想知道自己到底在怕什么。
- 我想知道哪个声音在控制我。
- 我想知道哪个声音一直被我压住。
- 我想知道这次纠结和我过去的模式有什么关系。
- 我想知道我到底是在选择，还是在逃避。
- 我想重新获得一点对自己的主权。

所以 ParallelMe 不应该直接给答案。

它应该让用户完成一次心理动作：

> 从「被内在声音拖着走」，变成「能够召集、倾听、质询、任命、调整自己的内在声音」。

### 1.3 产品本体

ParallelMe 的产品本体是：

> **阁**

阁不是一次对话，不是五个 bot，也不是一个历史列表。

阁是用户长期拥有的内在组织。

它具备四个特性：

1. **可管理**  
   用户可以查看、命名、转正、暂停、合并、请出自己的席位。

2. **可调用**  
   每次议题出现时，系统从阁中召集最相关的席位开会。

3. **有记忆**  
   每个席位记得自己出现过的场景、说过的话、被采纳的次数、被压住的历史。

4. **会演化**  
   临时席可以转正，常任席可以沉默，某个被忽视的声音可以被重新请回。

## 2 · 心理学规范

V3 必须有心理学规范，否则「动态人格」容易变成好玩的角色扮演。

我们的原则：

> 每个席位不是人设，而是一种被激活的心理功能。

### 2.1 IFS · Internal Family Systems

IFS 给我们最重要的产品原则：

- 人有多个 parts。
- 每个 part 都在保护用户，即使方式笨拙、极端或痛苦。
- 目标不是消灭某个 part，而是让 Self 与 parts 建立关系。
- Self 的状态是好奇、清晰、平静、有同情心、有边界。

产品转译：

- 每个席位都必须有「它在保护什么」。
- 每个席位都必须有「它最害怕什么」。
- NowMe 不是第六个声音，而是用户恢复主权后的裁决者。
- 系统不说「你这个声音错了」，只说「它在用什么方式保护你」。

### 2.2 Voice Dialogue · 多个自我与 Aware Ego

Voice Dialogue 给我们第二个核心原则：

- 人的内在有 many selves。
- 问题不在于某个 self 存在，而在于用户被某个 self 完全接管。
- 成熟不是选择一个声音永远正确，而是发展出 Aware Ego，能听见多个声音但不被其中任何一个绑架。

产品转译：

- 会议的目的不是让某个席位胜利，而是让用户不再被单一席位劫持。
- 「签字」动作代表用户从被动听建议，回到主动承担选择。
- 权力图谱要显示谁常常掌权、谁常常沉默、谁总在关键场景接管用户。

### 2.3 Schema Therapy · Modes

Schema Therapy 的「modes」可以规范组阁：

- 一个议题会激活不同的情绪状态和应对模式。
- 常见模式包括受伤小孩、愤怒小孩、顺从者、逃避者、惩罚性父母、健康成人等。

产品转译：

- 组阁不能只根据主题分类，还要识别「当前激活的模式」。
- 临时席通常从模式里长出来，例如「怕丢脸的我」「不想让人失望的我」「反抗的我」。
- 常任席必须覆盖稳定心理功能，临时席必须贴近具体议题和当下情绪。

### 2.4 Chairwork · 椅子技术

Chairwork 给我们 UI 和交互上的启发：

- 把内在冲突分开放在不同椅子上。
- 用户可以站在不同位置说话，也可以回到自己的位置作选择。

产品转译：

- UI 应该像席位，而不是普通聊天流。
- 用户可以点名某个席位，也可以「换位回答」。
- 会议室是强隐喻，用户要感觉自己真的在主持一场内在会议。

### 2.5 ACT · 价值与承诺行动

ACT 给我们裁决环节的规范：

- 焦虑不一定要消失，用户仍然可以按价值行动。
- 重要的不是想清楚所有事，而是做一个与价值一致的下一步。

产品转译：

- NowMe 的结尾不是建议，而是「承诺行动」。
- 下一步必须是 24 小时内可执行的小动作。
- 签字不是保证人生正确，而是承认「我愿意为这个选择承担一点代价」。

### 2.6 安全边界

ParallelMe 不是心理治疗替代品。

产品语言禁止：

- 诊断用户。
- 给医学化标签。
- 声称治愈焦虑或抑郁。
- 用权威口吻替用户决定人生。
- 鼓励自伤、断联、冲动辞职、重大财务行为。

产品语言应该：

- 命名感受。
- 识别保护功能。
- 提供低风险下一步。
- 保留用户主权。
- 在高风险内容出现时温和转向安全支持。

## 3 · 核心对象定义

### 3.1 阁

阁是用户长期拥有的内在组织。

用户可见属性：

- 常任席
- 临时席
- 沉默席
- 被流放席
- 本周掌权
- 本周在野
- 最近冲突最强的关系
- 最近最值得重新请回的声音

用户可以做的事：

- 查看席位。
- 改名。
- 写备注。
- 转为常任席。
- 让某个席位休席一段时间。
- 合并两个相似席位。
- 从历史会议中重新召回某个席位。

### 3.2 席位

席位是一个内在声音的产品化形态。

每个席位都必须有：

- 名称：用户能一眼懂。
- 类型：常任席 / 临时席 / 旁听席 / 沉默席 / 被流放席。
- 心理职能：它在保护什么。
- 核心价值：它只为一件事说话。
- 恐惧：它最怕发生什么。
- 证据偏好：它会抓住什么材料说服用户。
- 语言风格：它怎样说话。
- 阴影风险：它过度掌权时会造成什么代价。
- 记忆：它出现过哪些会议，是否被采纳。

### 3.3 常任席

常任席是用户长期稳定的心理功能。

默认五声是初始常任席模板，但不是永远固定。

默认常任五席：

| 用户名 | 内在席位 | 心理职能 | 保护对象 | 阴影风险 |
|---|---|---|---|---|
| 躺平的我 | 休整席 | 防止过劳、自我剥削和崩溃 | 身体、睡眠、低消耗生存 | 逃避行动、过度缩回 |
| 搞钱的我 | 资源席 | 计算资源、风险、现金流和机会成本 | 生存安全、选择权 | 把所有价值折算成钱 |
| 出走的我 | 自由席 | 通过空间变化和离开现场恢复生命力 | 自由感、探索欲、喘息 | 冲动逃离、切断关系 |
| 讨妈欢心的我 | 依恋席 | 维护关系、回应期待、避免让重要的人失望 | 被爱、归属、家庭连接 | 讨好、内疚、牺牲自己 |
| 5 年后的我 | 远望席 | 用时间尺度稀释当下焦虑 | 长期视角、人生连续性 | 抽离当下、低估即时痛苦 |

### 3.4 临时席

临时席由具体议题召集。

它不是随机生成的角色，而是从本次冲突中显影出来的心理功能。

例子：

职业议题：

- 想证明自己的我
- 害怕被淘汰的我
- 身体先投降的我
- 不想再打工的我
- 履历焦虑的我

关系议题：

- 怕伤人的我
- 想被坚定选择的我
- 不想再解释的我
- 害怕孤独的我
- 还在等对方变好的我

家庭议题：

- 乖孩子的我
- 反抗的我
- 内疚的我
- 想逃离饭桌的我
- 小时候的我

创业议题：

- 产品经理的我
- 风控的我
- 投资人视角的我
- 增长焦虑的我
- 不服输的我

### 3.5 旁听席

旁听席不参与主发言，但可以被用户点名。

它的作用：

- 让会议不臃肿。
- 让用户知道某些声音存在，但本次不是主角。
- 为用户提供「我想听它」的主动权。

### 3.6 裁决席

裁决席只有一个：

> 此刻的我

它不是一个普通席位。

它的任务不是综合，不是讨好，不是做中庸总结。

它要做四件事：

1. 我听见了谁。
2. 我决定暂时不听谁。
3. 我承认这个决定会失去什么。
4. 我接下来 24 小时做什么。

### 3.7 书记

书记不是人格。

书记负责：

- 记录会议档案。
- 抽取议题。
- 归纳权力变化。
- 提醒用户上次承诺。

用户不应该感觉自己在和书记聊天。

书记像纸页边缘的手写侧记。

## 4 · 完整用户旅程

V3 的主流程叫：

> 内阁会议

完整闭环：

```
提出议题
→ 立案
→ 组阁
→ 初表态
→ 用户点名
→ 交叉质询
→ 议案修订
→ 裁决
→ 签字
→ 归档
→ 更新阁
```

### 4.1 提出议题

首页第一屏只问一件事：

> 今天要开什么会？

输入框提示语：

- 把那件你反复想、但没人能替你决定的事写下来。
- 写成一句「我该不该……」也可以。
- 越具体，组阁越准。

按钮：

- 提交议题

不要叫：

- 发送
- 开始聊天
- 生成

### 4.2 立案

用户输入后，系统先不让席位发言。

系统先把混乱输入重写为「本次议题」。

例子：

用户输入：

> 我妈让我考公，我现在大厂月薪 2.5w，回老家可能 6k，我纠结半年了。

系统立案：

> 本次议题：我要不要牺牲收入和城市自由，换取妈妈眼里的稳定？

同时显示三个「可能的核心冲突」：

- 收入自由 vs 家庭安心
- 自我选择 vs 不让妈妈失望
- 眼前安全 vs 长期身份

用户操作：

- 就按这个开会
- 改一下议题
- 其实不是这个

这是第一处关键互动。

它让用户感觉：

> 产品不是套模板回答我，而是在帮我把问题问准。

### 4.3 组阁

立案后进入「本次组阁」。

系统提出五个发言席和若干旁听席。

界面文案：

> 本次会议，建议这些声音入席。

席位卡片必须显示：

- 席位名
- 常任/临时标签
- 为什么请它
- 它会保护什么
- 它过度掌权的风险

例子：

```
搞钱的我 · 常任席
请它入席：本次议题涉及 19k/月收入差。
它保护：你的现金流和未来选择权。
风险：它可能把所有事都算成钱。
```

```
怕选错的我 · 临时席
请它入席：纠结半年，说明真正困住你的可能不是考公，而是不可逆感。
它保护：你不被一个错误选择毁掉。
风险：它会让你永远停在比较里。
```

用户操作：

- 确认组阁
- 替换一个席位
- 新增一个声音
- 让某个声音旁听

这是第二处关键互动。

它让用户拥有对「阁」的管理感。

### 4.4 初表态

五个发言席依次表态。

每个席位只输出四项：

- 投票：赞成 / 反对 / 暂缓 / 另提案
- 理由：一句话
- 恐惧：我最怕……
- 要求：我要求你接下来……

不要一上来给长篇散文。

例子：

```
搞钱的我
投票：反对考公
理由：19k/月差额不是情绪，是五年后的一套首付。
恐惧：你用稳定换掉选择权。
要求：先把五年现金流写出来。
```

### 4.5 用户点名

初表态后，系统必须停下来。

不要自动进入下一阶段。

用户必须至少参与一次。

可选操作：

- 点名一个席位展开说。
- 质疑一个席位。
- 替某个席位补一句。
- 回答某个席位的问题。
- 请旁听席发言。

推荐快捷问题：

- 你真正想保护我什么？
- 你是不是在吓我？
- 如果我不听你，你会怎样？
- 你能不能说得更具体？
- 你这句话让我不舒服，为什么？

这是 V3 最重要的参与感来源。

产品必须从这里开始「深挖」。

### 4.6 交叉质询

系统根据投票、恐惧、价值冲突挑出两组最尖锐冲突。

质询不是互怼，而是有规则的会议程序。

规则：

- 每个席位只能问一个问题。
- 被问者必须回答。
- 用户可以判定「问中了」或「没问中」。
- 用户可以插话。

示例：

```
搞钱的我质询讨妈欢心的我：
你说让妈妈安心，可让她安心的代价是谁在付？

讨妈欢心的我回应：
是你在付。但你真的以为她要的是你的钱吗？她怕的是你离她越来越远。

用户选择：
[问中了] [没问中] [我想回答]
```

用户的判定会影响本次裁决和长期权力变化。

### 4.7 议案修订

经过追问和质询后，系统应允许议题变化。

因为很多用户一开始提出的问题只是表层问题。

例子：

原议题：

> 我要不要考公？

修订后议题：

> 我要如何在不把自己交出去的前提下，让妈妈知道我没有抛下她？

用户操作：

- 使用新议题裁决
- 保留原议题
- 两个都记入档案

这是产品高级感的关键。

用户会感觉：

> 它不是回答了我的问题，它帮我发现我真正的问题。

### 4.8 裁决

裁决由「此刻的我」完成。

输出结构固定：

1. **我听见了什么**  
   不超过 3 句，点名最关键的声音。

2. **我决定暂时听谁**  
   明确选择一个主导方向。

3. **我决定暂时不听谁**  
   必须承认一个被放下的声音。

4. **我承认这个选择的代价**  
   不许假装无损。

5. **接下来 24 小时**  
   一个具体动作。

禁用词：

- 平衡
- 兼顾
- 都很重要
- 看情况
- 综合考虑
- 再想想

逃生口：

> 我在逃避。

当系统判断用户仍然无法裁决时，可以允许「我在逃避」成为诚实结果。

但必须指出逃避的真相。

### 4.9 签字

裁决后不直接结束。

用户需要签字。

签字不是法律承诺，而是产品仪式。

按钮：

- 签字
- 暂缓
- 重新开会
- 我在逃避

签字文案：

> 我知道这不是完美答案。  
> 我愿意先为这个 24 小时动作负责。

签字后形成承诺：

- 动作
- 截止时间
- 可能阻止我的席位
- 下一次回来要追问的问题

### 4.10 归档

会议结束后生成「会议档案」。

档案内容：

- 本次议题
- 修订议题
- 本次组阁
- 投票结果
- 最响席位
- 被压住席位
- 最尖锐质询
- 用户判定
- NowMe 裁决
- 24 小时动作
- 是否签字

档案会更新阁。

## 5 · 阁的演化机制

### 5.1 临时席转正

当某个临时席反复出现，系统提示：

> 「怕让别人失望的我」已经连续出现在 4 次会议中。  
> 它好像不是临时来访者。  
> 要不要给它一个固定席位？

用户操作：

- 设为常任席
- 继续临时
- 改名后设为常任席

### 5.2 常任席沉默

如果某个常任席长期未被召集，或发言总被跳过：

> 最近 7 次会议里，「出走的我」只出现过 1 次。  
> 它没有消失，只是你很少让它开口。

用户操作：

- 下次优先请它
- 进入沉默席
- 暂时休席

### 5.3 被流放席

被流放席不是坏席位。

它通常代表用户不愿意听、听了会痛、但很可能携带关键信息的声音。

判断信号：

- 经常被强烈反驳。
- 经常被用户跳过。
- 经常在质询中问中，但裁决时被放下。
- 经常关联强烈情绪。

文案：

> 它不是错了。  
> 它只是每次一开口，你就想把门关上。

### 5.4 席位关系

席位之间有关系。

关系类型：

- 强冲突
- 压制
- 保护
- 联盟
- 调停
- 误解

例子：

```
搞钱的我 ←强冲突→ 出走的我
讨妈欢心的我 ←压制→ 出走的我
5 年后的我 ←调停→ 躺平的我
怕丢脸的我 ←联盟→ 搞钱的我
```

关系图的目的不是数据炫技，而是让用户看见：

> 我内耗不是因为我矛盾，而是因为我的几个内在席位长期没有被好好安排。

### 5.5 权力变化

每次会议后，阁会更新权力结构。

建议指标：

- 发言权：最近被召集和发言的频率。
- 采纳率：裁决是否听了它。
- 质询命中率：用户是否觉得它问中了。
- 压制率：它是否频繁被放下。
- 完成率：听它后的承诺是否完成。
- 情绪强度：它出现时用户的情绪强度。

用户可见表达不要叫指标。

用更产品化的语言：

- 本周掌权
- 本周在野
- 最近变强
- 最近沉默
- 最常问中
- 最常被你按下

### 6.1 会议

主入口。

- 五声

- 开会

最终用户语言建议：

> **会议**

## 7 · 核心页面设计

### 7.1 页面一：会议首页

第一屏目标：

> 让用户立刻知道这是一个开会的地方，不是聊天框。

视觉构成：

- 顶部小字：ParallelMe · 内阁会议
- 主标题：今天要开什么会？
- 副文案：写下那个没人能替你决定的议题。
- 中央输入区：像一张待立案的纸。
- 底部三个轻提示：职业 / 关系 / 家庭 / 自我，不做成模板按钮。

交互：

- 用户输入后，按钮从「提交议题」变成「立案」。
- 不直接显示五声。
- 进入立案页。

视觉气质：

- 大面积纸面留白。
- 字体有书卷感，但控件要克制。
- 不用聊天气泡。
- 不用科技感渐变。

### 7.2 页面二：立案页

目标：

> 把用户的混乱输入变成一个值得开会的议题。

布局：

```
左侧/上方：原始输入
中央：本次议题
下方：核心冲突
底部：用户确认按钮
```

关键 UI：

- 「本次议题」像会议标题。
- 「核心冲突」像三个印在纸边的标签。
- 用户可以直接编辑议题文字。

按钮：

- 就按这个开会
- 改一下
- 其实不是这个

### 7.3 页面三：组阁页

目标：

> 让用户感到这次会议是为这个议题临时组成的。

布局：

```
本次组阁

发言席 5 个
[席位] [席位] [席位] [席位] [席位]

旁听席 0-3 个
[席位] [席位]

底部操作
[确认组阁] [替换席位] [新增声音]
```

席位卡片内容：

- 名称
- 常任/临时
- 请它入席的理由
- 它保护什么
- 它的风险

微交互：

- 点击席位展开详情。
- 拖动席位调整发言顺序。
- 点击「旁听」把发言席降为旁听席。
- 点击「入席」把旁听席升为发言席。

### 7.4 页面四：会议进行页

目标：

> 让用户像主持会议，而不是看 AI 输出。

桌面布局：

```
顶部：议题 + 阶段进度

中间：五个席位围绕会议纸

右侧：当前发言 / 质询

底部：用户发言区
```

移动端布局：

```
顶部：议题 + 阶段
中间：当前发言席
下方：席位横向切换
底部：用户操作
```

阶段进度：

```
立案 → 组阁 → 表态 → 点名 → 质询 → 裁决 → 签字
```

每一阶段必须有明确的用户动作。

### 7.5 页面五：裁决与签字页

目标：

> 让选择变成一个有重量的动作。

视觉：

- 像一张会议决议。
- NowMe 的裁决不放在普通卡片里，而像正文。
- 签字区在底部。

结构：

```
会议决议

我听见了什么
我决定暂时听谁
我决定暂时不听谁
我承认代价
接下来 24 小时

[签字] [暂缓] [重新开会] [我在逃避]
```

签字完成后出现：

> 已归档。  
> 下次回来，我会问你这件事做了吗。

### 7.6 页面六：我的阁

目标：

> 让用户看到自己的内在组织正在形成。

首屏模块：

- 本周掌权
- 最近沉默
- 最常问中
- 等待转正的临时席

核心区域：

1. **常任席**
   - 默认五席 + 用户转正的席位。
   - 每个席位显示最近一次发言和权力状态。

2. **临时席**
   - 最近出现过但还未转正。
   - 显示出现次数和出现议题。

3. **沉默席**
   - 很久没有发言或被用户长期跳过。

4. **被流放席**
   - 用户强烈回避但频繁出现的声音。

5. **关系图**
   - 不做复杂数据可视化。
   - 像一张手绘关系地图。

### 7.7 页面七：席位详情

目标：

> 让每个席位像用户认识很久的一个内在角色。

内容：

- 名称
- 用户备注
- 它保护什么
- 它最怕什么
- 它常出现的议题
- 它最近问中过什么
- 它被采纳后发生过什么
- 它过度掌权的代价
- 它和谁冲突

管理操作：

- 改名
- 转为常任席
- 休席一段时间
- 合并相似席位
- 下次会议请它

## 8 · UI 美学系统

### 8.1 总体气质

关键词：

- 纸面
- 会议
- 手写侧记
- 低声但有重量
- 私密
- 克制
- 有仪式感

不要：

- SaaS 仪表盘感。
- 情绪陪伴 app 的糖水感。
- 心理测试网站的廉价感。
- 赛博 AI 工具感。
- 大面积霓虹、玻璃拟态、紫蓝渐变。

### 8.2 视觉隐喻

V2 是「纸页」。

V3 应该是：

> **纸面上的会议室。**

可用元素：

- 会议议案纸
- 席位名牌
- 侧记
- 签字
- 印章
- 档案夹
- 线装册
- 圆桌
- 手写批注

不要真的做成政府机关风。

我们要的是「内在会议」的仪式，不是行政系统的冷。

### 8.3 色彩

保留 V2 纸面底色：

- Paper: `#FAF6EC`
- Ink: `#14161A`
- Ink 2: `#3A3D45`
- Ink 3: `#7A7E88`
- Rule: `#E6E0D4`

席位色继续保留五声色，但降低面积：

- 休整席：雾蓝
- 资源席：古金
- 自由席：苔绿
- 依恋席：陶土
- 远望席：紫罗兰

新增状态色：

- 常任席：深墨
- 临时席：浅金
- 沉默席：低饱和灰蓝
- 被流放席：暗陶土
- 已签字：墨黑 + 小金印

原则：

- 背景永远克制。
- 色彩用于席位识别和状态，不用于装饰堆叠。
- 不使用大面积单一色块。

### 8.4 字体

标题：

- 宋体/思源宋体气质。
- 大标题少而重。

正文：

- 系统 sans。
- 长文可读性优先。

数字和标签：

- 小号、字距略开。
- 像档案标签，不像数据报表。

### 8.5 布局

原则：

- 第一屏必须有清晰主动作。
- 不使用卡片套卡片。
- 页面区块像纸张上的区域，而不是浮动面板。
- 固定格式控件要有稳定尺寸，避免流式内容导致跳动。

会议页：

- 桌面可以用圆桌/席位布局。
- 移动端不能硬做圆桌，改为席位横向切换 + 当前发言主面板。

### 8.6 动效

动效应该像纸和墨：

- 淡入
- 轻微位移
- 墨迹展开
- 签字后轻印章
- 席位入席时轻轻落座

不要：

- 炫技 3D。
- 大幅弹跳。
- 过度粒子。
- 频繁震动。

## 9 · 关键交互设计

### 9.1 用户必须参与的节点

V3 最大问题要解决「用户只是观看」。

因此每次会议至少设置三个必须参与点：

1. 立案确认
2. 点名追问
3. 签字或暂缓

可选参与点：

- 替换席位
- 质询判定
- 修改议题
- 请旁听席发言

### 9.2 点名追问

点名追问是深挖入口。

快捷问题要非常锋利：

- 你真正想保护我什么？
- 你最怕我承认什么？
- 如果我不听你，你会怎样？
- 你这句话来自哪一次经历？
- 你是不是把过去的事拿来吓现在的我？
- 你能不能给我一个具体画面？

不要用：

- 详细解释一下
- 继续
- 展开

### 9.3 用户插话

用户随时可以插话。

插话类型：

- 我不同意这个议题。
- 我想回答这个声音。
- 我觉得它问中了。
- 我觉得它在吓我。
- 我想请另一个声音说话。

插话不能打乱产品结构。

它应该像会议中的「打断发言」，系统接住后回到阶段。

### 9.4 替换席位

替换席位不能做成普通 dropdown。

应该像：

> 你要请谁入席？

候选来源：

- 推荐临时席
- 我的常任席
- 最近沉默的席位
- 从档案中召回
- 新建一个声音

### 9.5 签字

签字是最重要的情绪峰值。

交互：

- 用户点击「签字」。
- 出现一行可编辑承诺动作。
- 用户确认。
- 页面出现轻印章或签字线。

文案：

> 这不是保证永远正确。  
> 这是我愿意先走一步。

## 10 · 首次使用体验

目标：

> 3 分钟内让用户觉得「它不是会说话，它真的在帮我主持我自己」。

首次使用不应该让用户先填复杂资料。

首会流程：

1. 用户输入议题。
2. 系统立案。
3. 系统组阁，其中至少 1 个临时席必须贴近用户输入。
4. 用户确认组阁。
5. 五席初表态。
6. 用户点名追问一个席位。
7. 两席质询。
8. NowMe 裁决。
9. 用户签字或暂缓。
10. 系统生成第一份会议档案。

首次结束后再提示：

> 如果你愿意，我可以开始记住你的阁。  
> 你可以先给自己留一个名字。

不要在一开始强制注册。

## 11 · 长期留存体验

### 11.1 回访开场

不要说欢迎回来。

要说具体事实：

> 3 天前，你签过一份决议：今晚给妈妈打 7 分钟电话。  
> 那天「讨妈欢心的我」被你放下了。  
> 做了吗？

用户选项：

- 做了
- 没做
- 忘了
- 我不想说

### 11.2 周度内阁侧记

每周生成一次轻量侧记。

不是报告，不是统计。

像旁观者手写：

> 这周，搞钱的我掌权 3 次。  
> 出走的我两次问中了你，但都被放下。  
> 你不是没有自由的声音，只是每次它一开口，你就先替现实说话。

### 11.3 转正时刻

临时席转正是强留存节点。

文案：

> 「怕让别人失望的我」又来了。  
> 这是它第 5 次出现在会议里。  
> 你要不要给它一个固定席位？

这个时刻会让用户感觉：

> 我的内在系统真的在长出来。

## 12 · 商业化方向

先不谈价格，只定义价值层。

免费层：

- 可开一次或少量会议。
- 有默认五席。
- 可生成会议档案。
- 本地短期记忆。

付费层真正卖的不是聊天次数。

付费层卖：

1. **长期阁记忆**  
   保存和演化用户的常任席、临时席、关系、权力变化。

2. **跨设备私密档案**  
   用户的会议档案和席位不丢。

3. **深度复盘**  
   月度侧记、关系模式、职业决策模式、家庭议题模式。

4. **席位管理**  
   自定义席位、转正、合并、召回、休席。

5. **导出资产**  
   导出「我的阁」为个人 prompt、PDF 或可携带的人格地图。

商业定位：

> 用户不是为一次回答付费，而是为一个越来越懂自己的内在系统付费。

## 13 · 产品原则

### 13.1 用户主权优先

系统可以召集、提问、记录、提醒。

但最终必须让用户签字。

### 13.2 每个声音都在保护用户

即使某个声音听起来极端、懦弱、功利、讨好，它也不是敌人。

产品永远问：

> 它在保护什么？

### 13.3 不追求中庸

裁决不是综合所有人。

裁决是：

> 我听见了，但这次我先这样做。

### 13.4 不让用户只看表演

每次会议必须至少让用户参与三次。

### 13.5 记忆必须可见、可删、可改

因为阁属于用户。

不是系统拥有用户。

### 13.6 美学服务于私密感

视觉要让用户敢写真话。

不要让用户觉得自己在填工具、做测试、看报表。

## 14 · V3 MVP 范围

第一版只需要打穿一个强闭环：

```
立案
→ 组阁
→ 初表态
→ 用户点名
→ 质询
→ 裁决
→ 签字
→ 档案
→ 阁更新
```

MVP 必须有：

- 动态组阁。
- 至少 1 个临时席。
- 用户可确认或替换席位。
- 初表态是结构化会议格式。
- 用户必须点名追问。
- 质询后用户可判定。
- NowMe 裁决必须有代价和 24 小时动作。
- 会议档案必须更新某个席位状态。
- 我的阁页面必须能看到一次会议后的变化。

MVP 可以暂缓：

- 完整账号系统。
- 复杂关系图。
- 多月报告。
- 自定义所有视觉主题。
- 高级导出。

## 15 · 验收标准

### 15.1 产品体验

用户第一次使用后，应能说出：

- 它帮我把问题问准了。
- 它请出来的声音确实像我这次问题里的几个我。
- 我不只是看它输出，我参与了。
- 最后那个裁决不是鸡汤，是我可以做的一步。
- 它记住了这次会议，并改变了我的阁。

### 15.2 UI 体验

页面应满足：

- 第一屏能看出这是内阁会议，不是聊天工具。
- 组阁页让人一眼懂谁入席、为什么入席。
- 会议页不会被长文本淹没。
- 用户随时知道现在处于哪个阶段。
- 签字动作有仪式感。
- 我的阁不像数据看板，而像私人档案室。

### 15.3 心理安全

系统应满足：

- 不诊断。
- 不命令。
- 不羞辱。
- 不把用户推向高风险冲动行动。
- 永远保留暂缓、我在逃避、不想说的出口。

## 16 · 未来形态

如果 V3 跑通，ParallelMe 最终可以成为：

> 一个长期陪用户建立内在秩序的私人系统。

它的增长不是靠更多 agent。

它的增长来自：

- 用户的席位越来越像自己。
- 用户的阁越来越完整。
- 用户能看见自己反复出现的模式。
- 用户能在重大选择前调用自己的内阁。
- 用户会舍不得丢掉这份内在档案。

终局形态：

> 每个人都有一个自己的阁。  
> 它不替你活。  
> 它只在你快听不见自己时，替你把那些声音请回桌边。
