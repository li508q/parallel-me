# V0.6+ 路线图

> V0.5 是一个完整可用的版本——5 + 1 席内阁会议、Quick / Full 双模式、本地优先工作区、4 道用户参与门、对话感时间线、24h 复盘、跨议题席位统计。
> V0.6+ 的方向不是"再加功能"，而是**让"阁"真的演化、让用户真的成为主持人、让会议真的有对话**。

本文沉淀 Week 5 反思中明确 defer 的内容，以及更长期的产品愿景。所有方向都附实施草案与优先级。

---

## 0 · 总命题

V0.5 验收标准（已达成）：

- ✅ 用户能跑通完整内阁会议（quick / full）
- ✅ 4 道用户参与门一道不能跳
- ✅ 反讨好 NowMe 拒绝平衡 / 兼顾 / 都很重要
- ✅ 心理安全红线（永不挽留 / 永不打卡 / 永不混淆 AI 与人 / 危机词 off-ramp）
- ✅ 数据本地化（IndexedDB），可导出，可删除
- ✅ Timeline + Dock + Console 对话感视觉

V0.6+ 的目标：

> **从"主持一场会议"升级到"经营一座阁"。**

会议是事件，阁是组织。V0.5 把事件做扎实了。V0.6+ 让组织开始演化。

---

## 1 · 阁的演化（Loop C / D · 优先级最高）

V0.5 的 5 席是固定常任席。V0.6 起引入**临时席**与**席位生命周期**。

### 1.1 临时席机制

**问题**：当前所有议题都用同一组 5 席。但有些议题真正激活的是别的声音——「怕选错的我」「想被坚定选择的我」「不想再解释的我」。这些不在常任名册里。

**方案**：

- assembly 阶段加 `+ 新增声音` 入口
- 用户填写：席位名（≤ 12 字）+ 它在保护什么（≤ 30 字）
- 后端 SSE 接受 `extraSeats: { name, protect, fear }[]` 参数
- 临时席使用通用模板 system prompt（不需要为每个临时席手写完整 persona），保留人格紧张度但不喧宾夺主
- Meeting 记录加 `temporarySeats: { id, name, protect, appearedAt, parentMeetingId }[]`

**模板 prompt 草案**（待定）：

```
你是用户内心的一个临时声音，名字叫「{name}」。
你只为一件事说话：{protect}。你最怕的是 {fear}。
说话风格 ≤ 80 字一段，第一人称，保持紧张感，绝对不"和稀泥"。
你不替用户做决定。你说出你这一面的真实想法。
```

### 1.2 Loop C · 临时席转正

**触发**：同一临时席（按名字模糊匹配）累计出现 ≥ 3 次。

**UI**：

- /cabinet 页面在「临时席」section 显示候补转正列表
- 点击 → 进入「转正确认」对话框：
  - 显示该临时席最近 3 次发言摘要
  - 用户可改名 / 改 protect / 改 fear
  - 决定：[设为常任] / [继续临时] / [合并到 X 常任席]

**数据层**：转正后，临时席的 system prompt 模板被冻结为正式 persona，写入用户专属的 `lib/selves.user.ts`（或 IndexedDB seats 表）。

**风险**：这接近"用户造 part"的滑坡。必须有上限——最多 8 个常任席（5 默认 + 3 用户转正）。超过就强制合并或归档。

### 1.3 Loop D · 沉默席召回

**触发**：某常任席连续 7 次会议未出席（quick mode 主题不匹配 + full mode 用户没主动召唤）。

**UI**：

- 主页 Cabinet snapshot 「最近沉默」卡：
  > 最近 7 次会议里，「出走的我」没出现过 1 次。
  > 它没有消失，只是你很少让它开口。
- 三按钮：[下次优先请它] / [进入沉默席] / [暂时休席]

### 1.4 被流放席

**判断信号**（自动推断，不显式询问用户）：

- 经常被强烈反驳
- 经常在质询中被用户判定"问中了"但裁决时被放下
- 关联强情绪关键词

**UI 处理**：

- 永远只在 /cabinet 显示，**不在主页突出**
- 用 `seat-exiled` 暗陶土小面积标记
- 不做大红警告，不引发威胁感
- 提供「重新请回」入口

**实施成本**：中——需要语义分析 + 行为追踪。

## 2 · 对话感的彻底深化（Week 5 deferred · 优先级高）

V0.5 把视觉对话感落到位（Timeline + Dock + Console）。V0.6+ 让**行为本身**也对话化。

### 2.1 HostConsole 意图识别

**当前**：底部输入框接受任意文字，作为 user-turn 写入 timeline，仅记录用 — 没有让 AI 真"听懂"用户在说什么。

**V0.6**：

- 用户输入文字 → 客户端先做 fast-path 字符串匹配（"等等"、"暂停"、"我想问 X"、"我不同意"、"继续"），命中即触发对应 stage transition
- 不命中则调一个**轻量分类器** LLM call（用便宜模型 like deepseek-chat），分类成：
  - `pause` — 暂停当前阶段，等待用户继续
  - `summon` — 召唤某席（自动识别名字）
  - `dissent` — 用户表态「我不同意 X」，记入 user marks
  - `continue` — 推进到下一阶段
  - `note` — 仅记录，不触发流程
- UI：用户输入后显示一个一行 ack（"它听懂了：你想问 5 年后的我"）+ 操作按钮（[就这样] / [取消，只记录]）—— 让 AI 解读可被用户校正

**好处**：用户可以**说话**而不是**点按钮**——这是真正的对话感。

### 2.2 NowMe 对话化

**当前**：NowMe 输出一段单段 verdict，编号 1/2/3 列表。

**V0.6**：

- 改 NowMe system prompt 为结构化倾听格式：

```
请按以下结构输出，每段一行：

1. 「我听见了 ___ 说……」 (具体引用某席原话)
2. 「我也听见了 ___ 说……」 (引用另一席)
3. 「此刻我决定暂时听 ___」 (明确选择)
4. 「我承认这会让我失去 ___」 (代价)
5. 「接下来 24 小时，我 ___」 (具体动作)
```

- 客户端按行 parse，timeline 上 verdict turn 渲染为分行块（每一行 italic + 引号）
- 用户可在 verdict 后**插一句修订**：
  > 「这一句不对，我其实更想听 X。」
  → 客户端记录用户修订，重新生成 NowMe 第 3-5 行（保留 1-2 行听到的部分不变）

### 2.3 议案修订对话化

**当前**：用户在 textarea 输入修订议题 → 选 [按原议题] / [按修订] / [都记入]。

**V0.6**：

- 引入小型对话子流程：
  - 系统先抛 1 个开放问题：「质询揭示了什么？真问题可能是另一个吗？」
  - 用户输入观察（≤ 100 字）
  - 系统用 LLM 提议 2-3 个修订议题候选（基于 cross-exam 内容）
  - 用户选一个 / 改一个 / 不修订
- UI：候选议题以 chips 形式 inline 出现，可点击进入 textarea 预填充

## 3 · 跨设备 + 私密同步（探索 · 优先级中）

V0.5 是严格本地。V0.6+ 提供**可选**跨设备同步，不破坏本地优先。

### 3.1 端到端加密同步

**架构选项**：

| 方案 | 优 | 劣 |
|---|---|---|
| **Dexie Cloud** | 官方支持，集成快 | 商业服务，订阅费 |
| **自建 Supabase + E2E** | 控制力强，免费 tier 够大 | 开发成本高 |
| **用户自管 GitHub Gist** | 极致私密（用户自己的 GitHub） | UX 复杂 |
| **iCloud / Google Drive 文件同步** | 平台级私密 | 跨平台不统一 |

**推荐**：先做 **Dexie Cloud E2E** + **JSON 文件导出/导入**双轨，用户自选。

### 3.2 用户口令加密（即使本地）

**触发**：用户在 /me 选择「给我的阁加一把锁」。

**机制**：WebCrypto + 用户口令派生 key（PBKDF2）→ 加密 IndexedDB 内容（透明层，所有读写自动加解密）。

**风险**：用户忘记口令 = 数据丢失。需要明确警告。

## 4 · 周度 / 长期叙事（优先级中）

V0.5 是事件级（每次会议）。V0.6+ 引入周度 / 月度叙事。

### 4.1 周度内阁侧记

**触发**：每周一次（用户开过会的那一周）。

**生成**：LLM 读过去 7 天的 meetings + cross-exam 命中 + 用户判定 → 生成一段 200 字内的旁观者侧记。

**示例文案**：

> 这周，搞钱的我掌权 3 次。
> 出走的我两次问中了你，但都被放下。
> 你不是没有自由的声音，只是每次它一开口，你就先替现实说话。

**展示**：/cabinet 顶部 banner，可点开看完整版；本身不发推送。

### 4.2 Wrapped 式季度报告

**触发**：累计签字 ≥ 12 次，主页主动提示「想看你这季度的内阁吗？」

**形态**：7 帧滑动故事，每帧一个数据点：

1. 你在 _N_ 次纠结里都坐到了桌边
2. 这季度最响的那个声音是 _X_
3. 你最常按下来的是 _Y_
4. **你今天回避的那个分身**（专门挑一个用户长期没召唤的常任席）← 制造好奇 + 分享驱动
5. 你说会做的事，做了 _M%_
6. 反复出现的议题：_topic_
7. 一句心理学侧记 + 「带走它」分享按钮

### 4.3 反复议题识别

**当前**：主页"反复议题"卡片是占位状态。

**V0.6**：

- 用 embeddings 给每个议题打 vector
- 新议题进来时计算与历史议题的余弦相似度
- 相似度 > 阈值 → 提示「这看起来像 N 周前的那次议题」
- 主页"反复议题"卡显示前 3 个簇

**实施成本**：高——需要本地 embedding 库（如 transformers.js）。可推到 V0.7。

## 5 · 商业化路径（探索）

V0.5 完全免费。V0.6+ **不强行商业化**，但准备好可选付费层。

### 5.1 商业化原则（已锁定 V3-IVY-FINAL）

- **不做订阅**（与 Replika / Character.ai 反向定位）
- **Lifetime Access** 一次性付款（参考 Mindscape）
- 免费层完整可用 —— 不阉割核心体验
- 付费层卖"长期价值" —— 不卖"更聪明的 AI"

### 5.2 付费层候选功能

| 功能 | 必要性 |
|---|---|
| 长期阁记忆（无限会议保留） | ★★★ 核心 |
| 跨设备私密同步 | ★★★ 核心 |
| 周度 / 月度侧记 | ★★ |
| 临时席无限自定义 | ★★ |
| 高级导出（PDF / 个人 prompt 包） | ★★ |
| 优先模型（更好的 LLM 兜底） | ✗ 反原则（不卷模型） |

### 5.3 价格区间（待调研）

参考 Mindscape lifetime ¥99-299。ParallelMe 可定 ¥199 lifetime。

## 6 · B2B 治疗师副线（远期探索）

V3-IVY-FINAL § 5 提到的 Unblend 启发。

**形态**：用户可一键导出「我的阁」为治疗师可读的 PDF，包含：

- 5 席权力变化曲线
- 反复议题清单
- 关键 verdict 的 IFS 解读
- 用户判定 hit / miss / i-want-to-answer 模式

**用途**：作为用户与人类治疗师 between-session 的辅助工具，**不替代治疗**。

**合规**：如做 B2B 需要 HIPAA / 中国《个人信息保护法》合规审查。**远期探索**，不是 V0.6 主线。

## 7 · 优先级与排序

按"对核心产品体验影响 × 实施成本"排序：

| 优先级 | 主题 | 影响 | 成本 |
|---|---|---|---|
| **P0** | 临时席机制（1.1） | 极高 | 中（前后端 + UI） |
| **P0** | HostConsole 意图识别（2.1） | 极高 | 中（fast-path + LLM 分类器） |
| **P0** | NowMe 对话化（2.2） | 高 | 低（仅 prompt + parse） |
| **P1** | Loop C 临时席转正（1.2） | 高 | 中 |
| **P1** | 议案修订对话化（2.3） | 中 | 中 |
| **P1** | 周度内阁侧记（4.1） | 高（留存） | 低 |
| **P2** | Loop D 沉默席召回（1.3） | 中 | 低 |
| **P2** | Wrapped 季度报告（4.2） | 中（分享驱动） | 中 |
| **P2** | E2E 跨设备同步（3.1） | 中 | 高 |
| **P3** | 反复议题识别（4.3） | 高 | 高（embedding） |
| **P3** | 被流放席（1.4） | 中 | 高 |
| **P3** | 商业化（5） | n/a | 低（视情况） |
| **P4** | B2B 治疗师副线（6） | n/a | 极高 |

**V0.6 打包目标**：完成 P0 三件（临时席 + 意图识别 + NowMe 对话化）+ P1 任意一件。

## 8 · 不会做的事

明确**永远不做**的方向（避免战略漂移）：

```
✗ 自建账号系统（违反"无登录可完整使用"）
✗ 卷大模型（违反"不卷模型，卷应用层"）
✗ Push 通知（违反"零打扰"）
✗ Streak / 打卡 / 徽章（违反 V3 心理安全军规第 7 条）
✗ Character.ai 风格的"角色市场"（违反"内在系统不是娱乐"）
✗ 内购解锁角色（席位不应当是商品）
✗ 视频 / 语音模拟 part（违反"克制 + 私密"）
✗ AI 主动发问"今天感觉如何"（违反"不打扰原则"）
✗ 对话内容用作模型训练（哪怕匿名 — 违反信任）
```

## 10 · 验收 V0.6（建议时间窗 · 4 周）

V0.6 完成时，用户应该能说出：

- "我在 assembly 阶段加了一个『怕选错的我』，它真的发了言。"
- "我打字说「等等，我想问搞钱」，系统真的暂停了。"

如果能说出这四条，V0.6 成功。
