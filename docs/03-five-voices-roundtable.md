# 五声圆桌

![Five voices persona architecture](images/five-voices-persona-architecture.png)

五声圆桌是 ParallelMe 的核心体验。它把用户的内在冲突从“脑子里一团乱”变成一场可观看、可追问、可继续推进的对话。

五个声音是固定的。它们不是随机生成的 agent，也不是五个普通观点，而是五种常见的保护逻辑。

## 五声架构

五声的权威定义位于 `lib/selves.ts`。

| 声音 | 产品角色 | 守护什么 | 过度掌权的代价 |
| --- | --- | --- | --- |
| 躺平的我 | 休息与神经系统保护者 | 睡眠、体力、最低消耗的活法 | 恢复可能变成逃避。 |
| 搞钱的我 | 现实与资源边界保护者 | 现金流、退路、风险下的尊严 | 意义和亲密可能被压成 ROI。 |
| 出走的我 | 自由与生命力保护者 | 出口、探索、重新开始的能力 | 把逃离误认为真正的自由。 |
| 被牵挂的我 | 关系与归属保护者 | 家人、伴侣、重要连接 | 替所有人的情绪负责。 |
| 5 年后的我 | 时间尺度与未来连续性 | 长期方向、未来自尊、复利能力 | 把当下真实痛苦抽象掉。 |

每个声音包含：

- IFS 类型
- 核心信念
- 唯一核心价值
- 最害怕的事
- 说话风格
- 禁忌词
- 守护意图
- 盔甲
- 代价
- 渴望
- 帮用户看清的方式
- 两声对话时的追问方式

这保证声音在不同会话中稳定，同时又能根据用户议题自然适配。

## 开场立论

![Roundtable runtime process](images/roundtable-runtime-process.png)

圆桌从五声结构化开场开始，由 `/api/roundtable` 的 `action: "opening"` 生成。

每个声音读取同一份用户确认后的议题材料，并返回：

| 字段 | 含义 |
| --- | --- |
| `thesis` | 这一声看到的痛苦本质。 |
| `pull` | 这一声主张的第一步。 |
| `concern` | 如果走这条路，用户必须吞下的苦果。 |
| `protected_value` | 这一声在守护的底线。 |
| `task_evidence` | 来自本次议题的具体依据。 |

开场立论是收敛结构。它先给用户一张地图，再进入自由探索。

开场使用严格结构化输出 `voice_opening_v2`。每个字段必须是非空、具体、符合该声音立场的自然语言；空字段、泛化建议和旧式助手口吻会被 schema 拒绝并触发修复/重试。

## 圆桌模式

开场后，用户可以用多种方式推进圆桌：

| 模式 | 实现类型 | 行为 |
| --- | --- | --- |
| 全员继续 | `continue_all` | 五声基于同一份历史快照并发发言。 |
| 问全桌 | `user_to_table` | 用户提出新问题，五声分别回应。 |
| 问一声 | `user_to_voice` | 只让目标声音回答，但它仍读取完整历史。 |
| 两声对话 | `duel` | 一个声音向另一个声音提出具体追问，目标声回应。 |
| 答复/反驳 | `user_reaction` | 用户反馈写入历史，供后续声音和书记员观察使用。 |

最重要的并发规则是：

> 同一并发批次中，五声拿到的是同一份历史快照，不能假装看见本批次里其他声音刚生成的内容。

这避免了虚假的串行戏剧化，也保留了“平行的我”的产品语义。

自由发言使用 `roundtable_voice_turn_v2`，两声追问与回应分别使用 `duel_question_v2` 和 `duel_response_v2`。这些 schema 只约束机器可读结构和最低质量边界，不替声音写内容。若单个声音在并发批次中连续失败，系统可以对该声音保守降级，以免整桌被单点失败拖断；但正常路径必须先经过结构化修复与重试。

## 对话边界

圆桌不是辩论赛，也不是专家委员会。它是用户内在保护逻辑的显影工具。

提示词约束包括：

- 每个声音只代表自己
- 不替用户做最终决定
- 不做“大家都有道理”的平均答案
- 书记员不在可见圆桌中下场
- 不假装看见同批次其他声音
- 发言短、具体、有场景，不写人格说明书

## 为什么是固定五声

产品不追求无限人格，而是稳定反复地呈现五种高频保护逻辑：

```text
身体与疲惫
  + 资源与生存
  + 自由与生命力
  + 关系与责任
  + 时间尺度与自尊
```

随着用户完成更多纸页，`/voices` 页面可以基于本地记录统计哪些声音常出现、哪些声音常被继续追问、哪些声音常参与两声对话。

## 成功标准

圆桌成功时，用户应该能说：

> 这些都是我，但没有任何一声可以单独替我开车。
